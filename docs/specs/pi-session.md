## Goal

用户可以在 prompt 中按名称引用其他 Pi session，无须手动查找文件或复制会话。模型可以搜索授权项目的历史正文，并在已有 session 中后台提问、接收结果或调整正在执行的任务。

## Solution

新增独立 Pi 扩展包 `@yesifan/pi-session`，提供两个输入框补全前缀：

- `@s:`：按名称搜索当前项目的 sessions。
- `@as:`：按名称搜索所有项目的 sessions。

候选随查询变化。选中后，仅将当前引用替换为以下文本，其中名称和路径使用真实值：

```text
Read or search <session name> <absolute path> if more context is needed.
```

文本留在输入框中供用户继续编辑；不会自动提交，也不会预先注入会话全文。

同时提供两个模型工具：

- `search-session`：搜索指定 cwd 的会话正文；cwd 未提供或为空时使用调用方当前 cwd。返回匹配 session 的信息、完整 ID、绝对文件路径，以及按换行分隔的匹配文本段，不返回行号，不保证消息边界。
- `ask-session`：仅通过完整 session ID 指定目标，在原有会话中后台执行问题并写入记录，完成后自动回报。再次 ask 即为继续提问；`steer: true` 调整本扩展正在执行的任务，不另设追问工具。

本次只编写 spec，不创建运行时包，不将未实现能力登记为现有功能。

## User Stories

1. 作为 Pi 用户，我希望通过 `@s:` 按名称搜索当前项目的历史讨论，以引用同项目背景。
2. 作为 Pi 用户，我希望通过 `@as:` 按名称搜索其他项目的会话，以复用跨项目背景。
3. 作为 Pi 用户，我希望后续查询能够反映会话新增或改名，以避免启动时静态列表过期。
4. 作为 Pi 用户，我希望选中候选后插入名称和绝对路径并保留其他文字，以便继续编辑或删除引用，自行决定何时发送。
5. 作为 Pi 用户，我希望同名候选具有项目目录、更新时间等辅助信息，以避免选错会话。
6. 作为 Pi 用户，我希望保留前缀无匹配时输入不变且不转为文件搜索，同时原有命令和文件补全继续工作。
7. 作为模型工具使用者，我希望搜索当前或显式授权 cwd 的历史正文，获得匹配文本、会话 ID 和路径，以进一步阅读或提问，而不需要建立独立索引。
8. 作为 Pi 用户，我希望 agent 用 ID 在已有会话中后台提问并自动收到结果，以继续原讨论而不分叉或切换当前编辑器会话。
9. 作为 Pi 用户，我希望通过 steer 调整本扩展的活动任务；普通 ask 遇到同一 ID 的活动任务时明确返回 busy，以避免本扩展重复启动。
10. 作为 Pi 用户，我希望其他 cwd 必须显式授权，未找到目标或没有可 steer 的任务时明确告知，以避免操作错误会话。

## Implementation Decisions

### 包与运行模式

- 独立 workspace 子包 `@yesifan/pi-session`，不依赖本仓库其他扩展包。pi-subagents 仅作为 cwd 授权和后台交互语义参考。
- 补全通过 Pi 公开 provider 包装接口接入，不替换编辑器；另注册两个模型工具。
- 输入框补全仅安装于终端交互模式。工具在其他模式的支持范围尚待确认，不据此承诺后台回报能力。
- 实施时遵循仓库的安装、发布 allowlist、类型检查、测试、根 README 登记、changeset 和发布内容验证约定。

### SDK 与 session 来源

- SDK 调研基线为仓库锁定的 Pi 1.1.0；实施时核对当时锁定版本的类型和实现，不仅依赖最新文档。
- 当前项目使用调用方会话上下文的 cwd；当前项目和全局发现分别复用 SDK 枚举能力。
- “所有项目”仅指 Pi 标准存储中 SDK 可发现的项目，不扫描磁盘上的任意自定义目录或 subagent 私有存储。
- 补全使用枚举结果中的名称和路径，不为获取名称而另行打开、迁移或修复 session。SDK 枚举本身可能读取 JSONL，不将其描述为纯元数据扫描。
- 返回或插入的文件路径必须绝对化，不能仅假定 SDK 返回值已是绝对路径。
- 优先复用公开 SDK 能力，不重写 session 文件解析，不维护独立搜索索引，不依赖内部 UI helper。

### 补全与插入

- `@s:` 和 `@as:` 是保留前缀；自动建议和 Tab 触发均由扩展处理，无候选也不交给内置 `@` 文件搜索。
- 非 session 引用请求的建议和插入完整委托原 provider，保留 `/` 命令、普通 `@文件路径` 及其他已安装 provider 包装器的行为。
- 扩展自己完成 session 引用替换，不使用内置文件补全插入逻辑。只替换当前引用，保留其前后其他 prompt，不自动发送。
- 名称或路径有空格时仍完整插入，不丢失或截断。
- 后续查询必须能看到新增或改名的 session，不只使用启动时快照；具体缓存或刷新策略由实现决定。
- 已取消或过期的查询不得覆盖较新的候选或输入。
- reload 或会话切换后补全仍可用，不累积重复 provider 注册。

### 正文搜索与 cwd 授权

- `search-session` 以 session 为结果单位，搜索正文而非仅名称；返回匹配文本段、session 名称（若有）、完整 ID、cwd、更新时间及绝对文件路径等 SDK 可用信息。
- 使用 `SessionManager.list/listAll` 提供的 `allMessagesText`。当前该字段包含 user/assistant 文本聚合，不包含完整的 toolResult、thinking 等内容；不承诺搜索这些未包含内容。
- 在聚合正文中匹配查询，以换行作为返回匹配文本段的截取边界。不返回行号，不承诺这些文本对应整条消息，不额外还原角色、消息 ID 或消息时间。
- SDK 提供聚合文本不等于提供公开搜索接口；扩展只实现所需的轻量匹配和换行截取，不复制内置 picker 的完整查询语言。
- 当前 cwd 默认允许；其他 cwd 必须配置白名单。参考 pi-subagents，对绝对路径 realpath 后精确匹配，不通过目录前缀授权所有子目录。具体配置文件和字段名待确认。
- 两个工具都应在读取正文或运行目标前验证所属 cwd 授权，不能通过 ID 解析绕过白名单。cwd 授权不是文件系统沙箱。
- 工具授权不改变 `@as:` 的全局名称发现范围；能发现名称不代表能搜索其正文或运行它。

### 按 ID 继续原会话

- `ask-session` 的目标标识只接受完整 session ID，不接受名称、模糊 ID 或文件路径作为替代标识。
- SDK 公开的 `SessionManager.findById(cwd, id, sessionDir?)` 支持指定 cwd 内完整 ID 匹配，返回路径，不检查占用。扩展应在授权范围内解析 ID；跨授权 cwd 的具体查找规则仍待确认。
- 继续原持久化 session，不分叉、不复制为私有 subagent session，也不切换用户编辑器会话。问题、回答及正常执行记录写入原 session。
- 普通 ask 接受后后台执行，完成后向发起调用的会话自动回报结果及目标 ID、绝对路径，不要求轮询。
- 第一版完全不判断目标是否已被其他实例打开：不做跨实例锁、占用检测、上下文同步或任务转交。用户明确接受并发风险。
- Pi 1.1.0 允许多个实例打开同一 session，但各自持有上下文，SDK 不协调后续写入。并发使用可能从旧上下文产生不同分支，不能将其视为顺序继续同一对话；不声称普通追加必然损坏文件。

### 最小活动任务状态与 steer

- 仅保留本扩展当前活动任务的内存映射：session ID 对应正在加载或运行的实例。不缓存空闲实例，不持久化任务表，不引入任务队列、锁文件或自建多阶段状态机。
- 普通 ask 在异步加载前占用该 ID；已有记录则返回 busy，不隐式排队。此检查仅防止本扩展内部重复启动，不判断外部实例占用。
- `steer: true` 仅查找本扩展活动实例并调用 SDK steering 能力，不启动另一执行、不产生独立完成报告。没有活动任务或尚未加载完成时明确拒绝；实例是否能接受 steer 交由 SDK 判断。
- 结束或失败时清除活动记录并释放实例；后续 ask 重新从原 session 文件加载。加载失败也不得留下永久 busy 记录。
- 报告所需的调用方关联由本次任务持有，不能因调用方切换会话而误投到新会话。
- 后台任务不承诺跨 reload、退出或重启恢复，也不提供持久化报告队列或重启补发。具体清理和在线失败报告策略待确认。

## Testing Decisions

补全以 provider 包装接口为主要测试边界，不建立完整终端端到端测试。工具以工具调用、SDK session 读写及后台回报接口为边界，不单独测试内部任务表结构。

- 使用隔离临时 session 存储，借助真实 SDK 枚举验证范围和元数据，不读取或修改用户真实会话；测试后清理目录。
- 验证 `@s:` 当前项目范围、`@as:` 跨项目范围、名称筛选，以及新增或改名可被后续查询发现。
- 覆盖自动建议与 Tab 两条路径；无匹配不触发文件搜索，取消或过期查询不覆盖新结果。
- 验证插入名称和绝对路径、名称与路径含空格、同名辅助展示、保留前后文字及不自动发送。
- 验证非 session 输入的建议和插入继续委托原 provider，包括 `/`、普通 `@文件` 及与其他包装器组合；在注册边界覆盖 reload 和会话切换。
- 搜索覆盖默认/空 cwd、授权 cwd、未授权目录、多项目隔离；返回正确 session ID、路径及按换行截取的匹配正文，不返回行号、不冒充整条消息。
- 提问使用隔离 session 与可控模型替身，验证完整 ID 定位、原会话写入而非分叉、后台接受与完成自动回报、再次 ask，以及不会切换编辑器会话或误投报告。不默认消耗真实模型额度。
- 验证同一 ID 普通 ask 的 busy 行为、加载期间重复调用、有效/无效 steer、加载或执行失败后的再次调用。测试可观察结果，不要求复杂内部状态机。
- 不将跨实例互斥、后台重启恢复或跨 reload 补投列为验收要求。
- 使用仓库 TypeScript 类型检查及 Vitest 实践；实现完成后运行受影响包检查、相关测试并验证发布内容。

## Out of Scope

- 本次不实现或发布运行时 package。
- 补全不自动注入会话全文、不自动提交 prompt，不保证模型读取引用文件；显式搜索返回匹配正文不受此限制。
- 不切换、重命名或删除目标 session；仅显式 ask 继续运行原会话。
- 不保证返回整条匹配消息，不返回行号，不建立独立搜索引擎或索引，不修改 Pi SDK 来增加搜索能力。
- 不扫描任意自定义存储，包括其他扩展的 subagent 私有存储。
- 不检测其他实例占用，不提供跨实例互斥、运行接管或上下文同步；steer 不能控制其他终端的执行。
- 不持久化任务状态，不恢复跨 reload/重启任务，不补发历史报告，不扩展为通用 subagent 编排系统。
- 不替换编辑器，不提供 RPC、JSON 或 print 模式的输入补全 UI。

## Further Notes

以下事项尚未确认，不作为已约定公开行为；实施前按需要确认：

- 无名 session 是否参与名称补全，以及显示/插入名称；是否排除当前 session、如何处理内存 session。
- 名称匹配与正文匹配的具体算法、排序、候选/结果数量，以及超长单行或大量匹配的返回上限。按换行截取不等于允许无限输出。
- 带空格名称的查询边界、引用 token 结束规则、同一 prompt 中多个引用，以及插入名称和路径的引用/转义形式。
- 同名候选的具体辅助字段，枚举失败提示和刷新策略。
- 工具配置位置和 schema；ask 是否显式接受 cwd，或在全部授权 cwd 中解析 ID，以及异常重复 ID 的处理。
- ask 是否拒绝调用方当前 session、目标分支选择、模型/工具/扩展配置的继承方式。
- 工具非交互模式支持范围，在线失败/取消的回报与清理策略，以及 reload 时如何释放正在运行的资源；不增加恢复承诺。

本地文档沿用原 spec 创建日期；后续对话已将“整条消息全文”收敛为“按换行截取的匹配正文”，将目标定位限定为完整 ID，并明确接受外部并发风险和不恢复后台任务。原始 Notion 文档可能保留较早约定，后续实施以本地 spec 为准。
