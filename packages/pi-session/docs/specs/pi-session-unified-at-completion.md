## Goal

用户在 Pi 编辑器中输入 `@`，即可从同一列表发现并引用文件或跨项目历史会话，无须记住会话专用前缀。

## Solution

在原生 `@` 文件补全中加入会话候选，按标题搜索当前项目和配置授权的外部项目。当前项目显示 `[session]标题`，外部项目显示 `[session 项目名]标题`；选中后插入 `@session[标题](完整ID)`，发送时在相同授权范围内按完整 ID 定位并展开引用。

本规格替代[原 pi-session 规格](pi-session.md)中 `@s:`、`@as:` 补全及发送解析的约定；其他行为不变。旧引用格式不再解析，这是破坏性变更。

## User Stories

1. 作为 Pi 用户，我希望输入 `@` 就能同时选择文件和会话，以免记忆不同入口。
2. 作为 Pi 用户，我希望通过标题关键词搜索当前项目与授权外部项目的会话，包括未出现在最近列表中的旧会话，以便找回历史讨论。
3. 作为 Pi 用户，我希望从候选显示区分当前项目和其他项目，并能区分同名会话，以免引用错误的讨论。
4. 作为 Pi 用户，我希望选中后保留可编辑的标题和完整 ID，发送时即使会话同名或改名也能定位原目标。
5. 作为 Pi 用户，我希望无自定义标题的会话也能按首条消息摘要查找，不因未命名而被排除。
6. 作为 Pi 用户，我希望文件、命令和其他补全功能继续正常工作；找不到引用或枚举失败时保留输入，以免意外丢失内容。

## Implementation Decisions

### 范围与展示

- 保持跨模式规格的补全注册与输入来源约定：interactive 和 rpc 输入展开，extension 输入保持不变。
- 当前工作目录的会话显示为 `[session]标题`，外部工作目录的会话显示为 `[session 项目名]标题`，项目名使用目录名。有自定义标题时使用自定义标题，否则使用首条消息摘要；两者均不可用时使用 `Untitled`。显示及插入的标题最多 80 个 Unicode 字符，超出时截断并以 `…` 结尾，完整 ID 不截断；搜索仍覆盖完整标题。同名候选提供足以区分项目和 ID 的辅助信息。
- 补全和引用解析仅覆盖当前工作目录及其 `.pi/pi-session/setting.json` 的 `externalDirectories` 中授权的目录；未配置时仅当前目录。沿用工具授权的规范化与精确目录匹配规则，不扩展到任意自定义存储或私有 subagent 存储。配置目录无效或不可用时会话发现整体失败，文件补全不受影响，提交时引用保留并警告，避免不完整索引误判重复 ID。

### 补全、筛选与排序

- 普通 `@` 同时触发文件和会话候选，文件候选在前、会话候选在后。文件查询交给 Pi 原生 provider，保留其搜索、排序和选中插入行为；会话结果不得改变文件结果的相对顺序。文件和会话分别最多展示 20 条。
- 裸 `@` 返回授权范围内最近更新的 20 个会话。`@关键词` 将同一查询交给原生文件 provider，同时搜索授权范围内的完整会话索引，而非仅筛选裸 `@` 的前 20 项。
- 忽略大小写匹配完整标题及候选显示文字（包括类型标签和项目名）；依次优先标题完全匹配、标题前缀匹配、标题包含，仅匹配标签或项目名的排在标题匹配之后。匹配程度相同时先当前项目，再按最近更新时间降序。先搜索排序，再截取前 20 项。裸 `@` 按最近更新时间降序，不因项目改变其排序。
- 一次连续补全过程复用会话索引，避免每次按键都扫描历史；选中候选、后续查询离开当前 `@` 上下文或移至另一个引用位置时清除索引，下次重新加载。Pi 不提供补全菜单关闭回调：按 Esc 后在同一位置重新打开可能沿用旧索引，直到上述条件触发刷新。异步过期结果不得覆盖较新的查询。
- 非 `@` 的命令和其他 provider 行为继续委托；兼容自动建议、Tab 触发及其他 provider 包装器，不替换编辑器。

### 选中与发送

- 选中任一会话插入 `@session[标题](完整ID)`，只替换当前补全内容，保留其他输入，不自动发送。标题中的 `]` 和 `\` 使用反斜杠转义，换行替换为空格；解析时还原转义后的标题。文件候选仍由原 provider 插入。
- 发送时仅解析该新格式，按完整 ID 在授权范围内定位目标，并沿用现有引用展开行为：以会话名称和绝对路径生成提示句，不自动注入全文。显示标题只供阅读，不作为身份或匹配依据，因此同名、改名或使用摘要的会话仍按选中 ID 定位。
- 未知或失效 ID 原样保留；枚举抛出错误或 SDK 返回的不同会话出现重复完整 ID 时，受影响的引用原样保留并警告。SDK 可能静默跳过不可读目录或会话，重复 ID 检测仅覆盖实际返回的结果，无法保证检测被跳过的会话或警告所有枚举错误。多个引用独立解析。
- 移除 `@s:` 和 `@as:` 专用补全入口；旧格式发送时按普通文本处理，不做兼容解析。原生文件补全仍可按普通 `@` 查询处理这些文本。

## Testing Decisions

以现有 provider 包装接口及输入 transform 为主要自动测试边界，验证用户可观察行为；使用隔离的 SDK 测试存储和离线替身，不读取用户真实会话或消耗模型额度。

- 输入 `@deploy`，匹配文件、当前项目和已授权外部项目的会话可同时出现在一个列表，未授权项目既不显示也不展开；验证候选显示、文件排序和原 provider 选中插入。覆盖自动建议、Tab、无结果及其他 provider 的委托。
- 构造超过 20 个会话，验证裸 `@` 取授权范围最近 20 个；输入旧会话标题仍能找到它。验证两类候选各自的 20 条上限、标题匹配优先于标签匹配、同等级当前项目优先及时间排序；`@session` 和项目名能匹配候选。
- 验证自定义标题、首条消息摘要和 `Untitled` 的显示、搜索，大小写不敏感，长标题显示与插入截断但仍可通过完整标题搜索，以及连续补全复用索引、上述清除条件触发后发现新增和改名；过期异步查询不能覆盖新结果。覆盖标题特殊字符转义和换行处理。
- 两个项目存在同名会话时，选中其中一个后输入框保留标题与完整 ID，提交后按 ID 展开到对应绝对路径；覆盖改名、摘要标题、多个引用、未知 ID、枚举失败和前后文本。
- 验证旧格式不再被专门补全或在发送时展开；后台输入保持不变。实施后运行受影响包的类型检查和相关测试，更新用户文档与 changeset，并按发布规则验证包内容。

## Out of Scope

不更改 `search-session` / `ask-session` 行为或 cwd 授权，不自动读取或注入会话正文，不添加自建持久化索引，不承诺 RPC、JSON 或 print 模式提供补全 UI，也不执行远端发布。

## Further Notes

用户确认终端手动测试通过，并将 issue 原定的所有项目范围收窄为当前项目及显式授权的外部项目。发现使用配置中的路径拼写及其 canonical 路径；其他符号链接拼写所存的会话可能遗漏，`ask-session` 仅查找 canonical cwd 的存储，也可能无法打开通过符号链接拼写发现的会话。已接受 Pi SDK 无补全关闭回调、以及可能静默跳过不可读会话的限制，见上文。SDK 使用 `(no messages)` 表示没有首条消息；仅凭 SDK 元数据无法区分该占位值和内容恰为该字符串的真实首条消息，两者均显示为 `Untitled`。
