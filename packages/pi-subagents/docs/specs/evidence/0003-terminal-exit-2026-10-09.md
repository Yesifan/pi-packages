## 独立源码核对

已只读核对工作区改写版及主 checkout 的旧 runtime；无法证明这些源码字节就是历史进程实际加载的版本。

- 旧实现先持久化 completed/outcome/error/delivery=pending，再保存 agent、释放 mount，最后仅在未 closing 时路由。存储或清理失败、发送抛错、关闭抑制、发送后 submitted 写盘失败均可能留下 pending。
- 改写版将 pendingChildren 同步转入 pendingReports，清理后再次检查 captured scope/parent 是否有效。shutdown 先标 closing，再中断后代，因此不向新 root 补投。
- parent 自身失败时会 interrupt 活动 descendants；这些 child 不单独报告。这是需要明确的政策边界，不是“每个 child 退出都通知”已经实现。
- root 发送没有独立 processed receipt；nested parent 使用 custom message 观察与后续持久 Pi entry/settled barrier。发送、记录、处理应分开验证。

这些证据支持新增异常退出通知规格，但不足以宣布已定位唯一根因或已修复。
