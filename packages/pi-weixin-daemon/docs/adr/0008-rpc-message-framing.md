# ADR-0008：RPC 消息边界

- 状态：已采纳（Accepted）
- 关联：Issue #30、#33、[ADR-0007](0007-account-name-id-boundary.md)

## 背景

UDS 是字节流，单次 data 回调不是消息边界。请求或响应分片会使原先逐块 JSON.parse 拒绝合法消息，UTF-8 字符也可能跨块。

## 决策

- 每个连接最多执行一次请求。客户端发送 JSON.stringify 生成的单行 JSON，并追加换行符作为请求边界。
- 服务端按字节缓冲至首个换行符，一次解码后分发；其后输入不再分发。完整请求前 EOF 不执行操作；等待请求期间设置 15 秒空闲超时，开始分发后禁用该读取超时。
- 响应沿用已有 socket.end 语义，以 EOF 为边界；客户端缓冲全部字节后统一解码并校验响应。
- 不猜测旧协议、不重试；已开始的操作不因客户端断开就被视为未执行。广播执行期间不施加请求读取超时，普通客户端仍保留既有空闲超时。

## 后果

请求换行边界是 BREAKING 变更，CLI 与 daemon 必须配套升级并重启；无换行的旧客户端请求不会在新 daemon 上执行。与 ADR-0007 的账号参数协议调整一起发布，不引入存储迁移。
