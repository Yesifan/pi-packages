# 需求 0006：活动 Pi 会话的统一最终文本回复

- 状态：已实现
- 目标版本：0.6.11
- 关联：[`ADR-0006`](../adr/0006-session-wide-agent-reply-routing.md)

## 背景与目标

目前微信入站消息调用 `SessionController.runTurn()` 时，pi-wx 仅在该调用期间收集 Pi 事件并发送最终回复。扩展或其他会话内机制在此后向同一个仍存活的 Pi 会话送入消息、触发独立 Agent 回合时，Pi 可以生成新的 assistant 回复，但没有微信回复收集器，结果只留在 Pi 会话中。

目标：只要该项目由 pi-wx 管理的 Pi 会话仍存活，**该会话任意来源触发的 Agent 回合**完成后，正常最终文本回复均按现有项目广播规则发送给微信参与者。回复发送不取决于是否存在对应的微信入站消息或 `TurnContext`；无需识别或依赖特定扩展（包括 pi-subagents）。

## 行为要求

1. 回复的收集范围覆盖当前活动 Pi 会话的整个生命周期；首个微信输入触发的回合与随后由会话内消息触发的独立回合遵循同一条正常文本广播路径。没有 Pi 会话、或旧会话已关闭/替换时，不转发其事件。
2. 以 SDK 的完整 Agent 回合结束信号为最终发送边界：重试、继续执行或 steer 并入同一回合时，不发送中间结果；有可发送的成功文本时每个完成的回合最多广播一次。没有最终文本的回合不发送空消息；仅出现消息但未启动 Agent 回合时不得无限等待结算事件。
3. 广播目标维持现有**项目级**参与者注册表语义：发送时选择已观察到、账号仍配置在该项目中的参与者，沿用已保存的微信回复上下文；`contextToken` 缺失仍按现有尽力发送与失败记录处理，不新增收件资格过滤。此需求不引入 session 专属收件人表，不向从未参与项目的账号猜测发送目标。单一目标发送失败不阻塞其他目标，记录发送成功/失败统计，不把 Pi 生成回复等同于微信已送达。
4. 微信入站消息仍按现有 busy、命令、UI 答复及发言互通规则处理。独立 Agent 回合执行及其回复投递期间，不能同时接受另一个会导致回复混线的微信回合；回合之间的回复发送需维持顺序，不重复广播。
5. 有微信发起者的回合继续保留现有超时、abort、Provider/模型错误、部分输出、extension warning 的定向处理。没有发起者的独立回合发生错误、abort 或仅有不完整输出时，不将不完整内容当作成功文本广播；记录可诊断的错误。文件发送、Extension UI、`weixin_send_progress` 和 typing 的既有定向规则不因本需求自动扩大范围。
6. session 替换（包括扩展主动切换 session）、主动停止、项目停止、空闲真实关闭及异常超时后，必须清理或隔离原 session 的回复收集状态；跨异步发送过程也需校验所属 session，迟到事件不得发送到新 session 的回合或被重复发送。

## 不在本需求范围

- 不改变默认 10 分钟空闲关闭策略；后台扩展静默执行但根 Pi 回合尚未开始时，可能仍被空闲关闭。独立 Agent 回合实际运行/投递期间须遵循 busy 状态，不能作为空闲会话关闭。
- 不增加 Pi 扩展专属回调、subagent 活动检测、持久化发送队列、跨 daemon 重启的补发保证或新的微信目标鉴权方式。
- 不把每个文本增量、工具进度或 Pi 消息都当成单独微信回复。

## 验收

1. 微信首个回合正常回复广播一次；它结束后，同一存活 session 由会话内消息触发的独立回合产生最终文本，项目已登记参与者收到一次广播。
2. steer 并入当前回合、自动重试、连续独立回合分别只有预期的最终回复；相邻回合的内容不混合、不漏发、不重复，发送顺序正确。
3. 独立回合运行和回复投递期间，微信新消息按 busy 规则处理；未启动 Agent 回合的输入不挂死。
4. 独立回合无文本、失败或 abort 时不广播空白或不完整文本，daemon 留有可诊断日志；已有微信回合的错误及 warning 定向行为保持不变。
5. session 替换/关闭、超时及迟到事件不把旧回合内容发给新 session；广播中的单个微信目标失败不影响其他目标。
6. 受影响包的类型检查、相关单元与集成测试通过。
