## Goal

微信用户希望将语音作为文字输入方式使用。Pi 只需要微信服务器提供的转录文本，不需要接收音频附件或文件路径，同时需要知道文本可能存在识别错误。

## Solution

收到有转录文本的微信语音时，只向 Pi 传递转录文本及固定备注，不再下载或携带语音文件。语音内容使用以下格式：

```text
xxxxx【以上为用户的语音转录的信息，可能有识别错误】
```

其中 `xxxxx` 是微信服务器提供的转录文本。转录为空时，直接向发送者回复提示，不将空语音交给 Pi。

## User Stories

1. 作为微信用户，我希望发送语音后，Pi 使用微信的转录文本处理我的请求，无需读取音频文件。
2. 作为微信用户，我希望 Pi 知道转录文本可能存在识别错误，避免将转录结果误认为完全准确的文字输入。
3. 作为微信用户，我希望转录为空时收到提示，而不是没有反馈或触发一次只有备注的 Agent 回合。

## Implementation Decisions

### 转录文本与附件

- 语音识别由微信服务器负责，使用消息中的 `voice_item.text`；不新增本地识别或外部转录服务。
- 转录原文用于现有命令、选择器和 UI 回复解析；仅在构造交给 Pi 的输入时，在对应语音文本末尾追加固定备注 `【以上为用户的语音转录的信息，可能有识别错误】`。不自动纠错、改写或猜测原意。
- 不下载、解密或保存入站语音音频，不向 Pi 传递语音附件、音频文件路径、保存提示或语音下载失败提示。即使消息携带有效音频下载信息，也不使用它。
- 普通文本、图片、文件和视频的现有处理保持不变；混合消息中的其他有效内容不因语音处理而被丢弃。
- 保留现有账号与项目路由、发送者标记、普通消息 busy 策略和回复规则，其他媒体能力不变。入站消息新增可选的 Agent 输入文本字段，未提供时回退到原始文本，兼容现有调用方。

### 空转录

- 缺失、空字符串或纯空白的转录均视为没有可用转录文本。
- 空转录时向实际发送者发送提示，使用该消息对应的账号、`senderId` 和 `context_token`，不向项目其他参与者广播提示。
- 仅包含空转录语音、没有其他有效输入的消息不交给 Pi，不因此创建会话或触发 Agent 回合。
- 混合消息存在其他有效内容时，保留其现有处理；空语音本身不生成备注或附件。
- 提示文案：`未获取到语音转录文本，请重新发送语音或改用文字。`。

### 职责与文档

- 微信接入层负责读取转录、保留原始文本与 Agent 输入的区分、跳过语音媒体下载并识别空转录；通过现有消息与回复链路完成提示。会话 prompt 构造使用带备注的 Agent 输入，不让备注干扰控制命令或 UI 交互。保持项目路由与会话职责边界，只有 Pi 适配层依赖 Pi SDK。
- 实施时同步更新 README 的媒体说明及相关用户文档，使其不再描述入站语音会下载到 inbox 或向 Pi 提供音频路径。
- 运行时行为修改时为 `@yesifan/pi-weixin-daemon` 添加 patch changeset。本 spec 不代表功能已实现。

## Testing Decisions

- 用户明确要求不为本需求新增测试，不增加新的自动化测试用例、测试文件或跨层测试边界。
- 实施时运行受影响包的类型检查和现有相关测试，确认已有消息归一化、媒体处理及会话行为未被破坏；若现有断言明确描述被本需求替代的旧语音行为，仅同步调整该断言。
- 本需求的可观察验收行为为：有转录时只传递文本及固定备注、无音频下载或附件；空转录时仅向发送者提示，不因空语音调用 Pi。验收行为不构成新增自动化测试的要求。
- 不要求调用真实微信或真实模型进行自动化验证。

## Out of Scope

- 本地或第三方语音识别、自动纠错、转录准确性校验。
- 音频分析、语气识别、音频转码及原始语音回退。
- 等待转录、轮询、重试或后续转录补发处理。
- 删除历史 inbox 中已保存的语音文件。
- 其他媒体处理、出站附件能力及无关重构。
- 新增测试、发布包或推送远端。

## Further Notes

- 用户确认不存在“消息暂时没有转录、之后补发转录”的情况；按当前消息携带的转录结果处理即可。
- 微信可能提供错误转录，保留原文并通过固定备注说明，不设计额外识别失败兜底。
- 实施前的实现将转录作为文本，同时可能下载语音并向 Pi 提供文件路径；本需求已替代该入站语音行为，不修改已完成的历史规格。
- 实现使用可选的 `promptText` 区分 Agent 输入与原始控制文本，保留语音命令、选择器及 UI 回复行为。独立审查通过，未新增或修改测试。
- Biome、受影响包类型检查和构建通过；相关消息、媒体、项目、会话及命令测试通过。离线全套测试为 157 项通过、4 项失败，失败集中在 `test/integration/rpc.test.ts` 的 Unix socket `listen EINVAL`，未作为通过处理。真实微信送达未验证。
