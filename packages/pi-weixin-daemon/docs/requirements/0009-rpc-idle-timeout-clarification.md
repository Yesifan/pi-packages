## 更正范围

Issue #34：更正需求 0007 的“15 秒总超时”措辞，保留原有实现和默认值，不引入新的请求总时限。

## 当前约定

- 普通 RPC 使用 `socket.setTimeout(15000)`，限制连续无活动的时间。持续收发数据会重置空闲计时，不能据此承诺请求在 15 秒内完成或失败。
- 广播使用 `socket.setTimeout(0)`，禁用客户端空闲超时，等待响应完成；微信单次请求仍有自己的超时。
- 超时不代表 daemon 未执行操作，不触发离线凭据清理，也不自动重试。

## 验证

保留 RPC 单测对普通调用 `15000`、广播 `0` 以及 timeout 拒绝且不误判离线的断言。文档与现有 Node socket 超时语义一致；不修改已完成的历史需求 0007。
